# xiaohongshu-ops-playbook

一套从真实账号跑出来的小红书垂类账号全链路运营规范：选题 → 文案 → 图文卡片 → 发布 → 数据复盘 → 每日学习沉淀。Agent 照此可独立运营一个 AI 教程类账号，人类只处理登录等机器做不了的环节。

> An executable operations playbook for running a Xiaohongshu (RED) tutorial account end-to-end with an AI agent: topic selection (with a hard academic-integrity red line), copywriting, card design, publishing, data review, and a daily learning loop that keeps the playbook itself evolving.

## 为什么做这个

市面上的小红书 Skill 大多是通用方法论（标题公式、算法因子、种草日历），写给"所有账号"看的。这套 playbook 相反：它来自一个真实账号 25 天的运营沉淀，所有的数字和规则都有出处——

- 攻坚期 14 篇跑出的流量结构：**搜索 82% vs 推荐 10%**，所以整套打法围绕搜索长尾，不追热点；
- 两次被平台判「扰乱管理秩序」换来的**学术红线**，优先级高于一切增长目标；
- 20:00 vs 21:30 发布时间 A/B 测试的真实结论；
- 每天 07:00 的学习沉淀，稳定结论自动写回本 playbook（见 [CHANGELOG.md](./CHANGELOG.md)）。

## 七章速览

0. **账号定位**——先定死再谈运营：AI 教程 × 学生党，图文为主，成功标准是搜索占比 ≥30%、收藏率 ≥3%、点击率 ≥6%。
1. **选题**——七类公式（痛点/数字/对比/稀缺/共鸣/资源/反常识）批量生产 + 爆款结构模板（DDL 钩子 + 反常识流程 + 收藏载体 + 可复制提示词）+ 三问校验。以及最重要的：**学术红线**。
2. **文案规范**——3 技巧结构（场景 + 步骤 + 可复制提示词 + 避坑）；标题 ≤20 字、正文 ≤950 字、标签 ≥8 个；结尾必须给"当场能用"的行动指令；发布勾选 AI 合成声明。
3. **图文卡片**——5 张 3:4 竖版（封面 + 3 教程卡 + 结尾卡），深色视觉规范，逐张目检清单。
4. **发布流程**——内容包提前一天备好；登录态亲自验证；直接发布不存草稿；发布后登记去重。
5. **数据复盘**——复盘阈值（点击率 <6% 改封面、停留 <30s 改开头、收藏率 <3% 改选题、搜索占比 <30% 改 SEO）；藏赞比持续 >2 的选题改写法；发前差异度自查。
6. **每日学习沉淀**——"学到了什么 → 怎么用到内容上 → 策略冲突检查"三段式，让 playbook 自己进化。

## 核心设计

### 学术红线（最高优先级）

**AI 是否在替学生产出要交上去 / 要上台讲的学术成品——是，即毙，与措辞无关。**

一切论文、毕设、答辩、开题报告、文献综述、课程论文的代做、代生成、润色、降重、查重规避，永不采用。合规的学生题材只限：考试复习方法、复习规划与时间管理、笔记整理方法、实习求职、学习工具使用技巧。被拒选题直接退役，绝不改头换面重发。

### 搜索优先，不追热点

教程垂类吃搜索长尾：标题 / 首段 / 标签共用同一关键词组，先定一个主要搜索意图再动笔。热点稀释账号标签，不做。

### 自己进化的 playbook

每天 07:00 学习新知识（平台治理动作、算法解读、爆款拆解），三段式沉淀；被自有数据验证的稳定结论自动写回 `SKILL.md`，变更记入 `CHANGELOG.md`。方法会过时，持续学习的系统不会。

## 安装

```bash
# Claude Code / Codex 等支持 Skills 的 Agent
npx skills add https://github.com/xiaoxiehang/xiaohongshu-ops-playbook
```

或直接把 `SKILL.md` 放到你的 skills 目录。

## 适用与不适用

- ✅ 垂类教程 / 知识 / 工具账号，图文为主，想建立可复用的运营系统
- ✅ 想让 Agent 独立执行选题→发布→复盘全链路
- ❌ 生活方式种草 / 电商带货（方法论不对口）
- ❌ 指望一套静态文档解决所有问题（这套 playbook 的价值在于持续更新）
